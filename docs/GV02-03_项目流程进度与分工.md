## 1. 项目目标

GV02-03 的目标是建立一条可复现的 GvpA 候选蛋白生成、鉴定、评价和筛选流程：

1. 使用序列 VAE（GAN 可作为后续对照）生成新的蛋白质候选；
2. 对生成序列进行格式、长度、复杂度、组成、重复和截断等质量控制；
3. 区分 GvpA、GvpJ、其他 Gvp 家族以及缺少证据的序列；
4. 只对具有较强 GvpA 计算证据的候选计算正式评价指标；
5. 从约束满足度、保守性、新颖性和多样性四个维度进行多目标评价；
6. 使用等权加权、Pareto 和分维度轮转三种策略产生 Top-K 候选；
7. 通过正负对照、消融、权重扰动、阈值扰动和随机基线检查结果是否合理、稳定；
8. 输出可追溯的候选名单、原始证据、图表、Manifest 和复现清单。

当前协作范围只覆盖数据、模型、评价和复现实现；PPT、答辩讲稿和报告排版暂不纳入五人技术分工，待最终实验结果稳定后再单独安排。

本项目得到的是“计算支持的候选优先级”，不是湿实验功能证明。应严格区分：

- **生成序列**：由模型产生，但尚未完成质量和家族核验；
- **计算支持的 GvpA 候选**：通过质量控制、家族鉴定和域门槛；
- **实验确认的功能 GvpA**：需要后续结构、表达、组装和功能实验，本项目不能直接确认。

### 4.2 暂定参考集清洗

当前清洗规则包括：

- 标题必须显式包含 GvpA；
- 排除显式 GvpJ；
- 排除 `partial`、`fragment`、`predicted`；
- 排除非标准氨基酸；
- 长度限制为 50～180 aa；
- 对完整序列进行精确去重；
- 保留来源到清洗 ID 的映射和排除原因。

当前结果：

```text

清洗后不同参考：1224 条
CD-HIT 90% 代表：418 条
```

该集合目前只能称为“暂定 GvpA 参考”，不能称为最终高可信 GvpA。

### 4.3 旧版参考比对与保守位点

已经完成：

### 5.5 GvpA/GvpJ/其他 Gvp 竞争性鉴定

每条 QC 通过候选应输出：

```text
sequence_id
pf00741_status
pf00741_score
pf00741_coverage
best_family
best_family_score
second_family
second_family_score
family_margin
family_status
classification_reason
```

候选至少分为：

```text
supported_gvpa
gvpa_gvpj_ambiguous
other_gvp
unsupported
```

不能把 PF00741 通过直接等同于 GvpA，也不能强行把证据接近的 GvpA/GvpJ 序列分到 GvpA。

### 5.6 真正的候选池

最终需要建立：

```text
主分析池 = qc_pass
          AND family_status == supported_gvpa
          AND domain_pass

歧义探索池 = qc_pass
            AND family_status == gvpa_gvpj_ambiguous

排除池 = QC失败、其他家族、无证据或域不通过
```

当前 `eligible_candidates.fasta` 只表示基础 QC 通过，不能作为最终 GvpA 主分析池。

如果主分析池不足 Top-K，应如实输出实际数量，不得从排除池自动补齐。

### 5.7 改进相似度和距离

当前使用 BLAST 最佳局部比对，并将无命中近似为 identity=0、distance=1，可能高估异常序列和异家族序列的多样性。

还需增加：

- BLASTP 或 DIAMOND 快速检索；
- 主分析候选的全局或半全局比对；
- query coverage 和 target coverage；
- 最低可靠覆盖门槛；
- 多 HSP 检查；
- 无可靠比对标记为 unresolved，而不是自动最大距离；
- 距离可信度；
- 主分析池与歧义池分别构建距离矩阵。

### 5.8 V2 四维评价

最终应按以下规则重算：

1. **约束满足度**：连续 PF00741 证据保留，但域门槛必须先通过；
2. **保守性**：只使用高可信 GvpA 参考定义保守位点；
3. **新颖性**：只对适用家族计算，相对于高可信天然 GvpA；
4. **多样性**：只在同类候选池中计算，无可靠比对不能自动视为最大差异。

### 5.9 硬门槛和 V2 筛选

正式顺序必须是：

```text
QC → 家族鉴定 → 域门槛 → 四维评分 → 多目标排序
```

不能让高新颖性或高独特性抵消 QC、家族或域失败。随后在主分析池内重跑等权、Pareto 和轮转，并重新生成 Top-10/20/50。

## 9. 协作推进方式

不将实现拆成大量固定阶段。五个人先并行开发各自模块，只有在需要真实上游数据时才进行必要的串联。

### 并行开发任务

- A：用现有天然数据开发并验证参考核验和家族分类；
- B：用当前暂定训练集开发 VAE、训练脚本和生成元数据；
- C：用现有旧候选开发高级 QC、相似度和距离模块；
- D：用当前 QC 结果开发候选池、四维评价、硬门槛和筛选接口；
- E：冻结配置和字段，开发流水线集成、端到端测试和复现检查。

### 必要的数据交接

只有以下交接必须按顺序完成：

```text
A 最终高可信参考
→ B 正式训练并生成候选
→ C 完整 QC
→ A 家族分类
→ C 同家族距离
→ D 正式评价和筛选
→ E 全流程复现检查
```

在此之前，各模块都可使用暂定数据进行开发和单元测试；最终输入到位后由 E 统一触发正式重跑。这样既避免等待，也避免将临时结果写成最终结论。

## 11. 最终验收标准

项目完成时应满足：

1. 训练参考经过 GvpA/GvpJ 竞争性核验；
2. 训练、验证和测试按同源簇隔离；
3. VAE 模型、词表、checkpoint、配置和训练过程可追溯；
4. 新候选及每条生成元数据完整；
5. 每条候选都有 QC、家族、域和四维证据；
6. PF00741 命中不再直接等同于 GvpA；
7. 非 GvpA 不会因高新颖性或高多样性进入主名单；
8. 新颖性相对于高可信天然 GvpA 计算；
9. 多样性只在同类候选中计算；
10. 无可靠比对不自动等价于最大距离；
11. 主名单只来自通过 QC、家族和域硬门槛的候选；
12. 合格候选不足时如实报告，不自动补齐；
13. 正负对照表现符合预期；
14. V2 消融和鲁棒性实验完成；
15. 两次正式运行结果能够复现或满足预先定义的容差；
16. 评分表、图表和 Manifest 中的数字一致；
17. 所有成员分工和过程证据真实可核验；
18. 技术说明始终区分“计算支持候选”和“实验确认蛋白”。
