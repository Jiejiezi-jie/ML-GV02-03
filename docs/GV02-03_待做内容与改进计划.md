# GV02-03 待做内容与改进计划

## 1. 文档目的

本文档记录 GV02-03 下一阶段需要完成的工作。项目将从“对已有混合 Gvp 候选池进行探索性评价”，调整为一条更严格、可追溯的流程：

> 使用 VAE 或 GAN 生成新的蛋白质候选，先完成质量控制和 Gvp 家族鉴定，再从可信 GvpA 候选中计算约束满足度、保守性、新颖性和多样性，最后在硬门槛下完成多目标筛选。

现有结果可以作为旧版基线，但不能直接作为修改后的最终结果。新流程完成后，评分表、Top-K 名单、图表、报告和答辩材料均需重新生成。

## 2. 当前基线与主要问题

当前项目已经完成：200 条 T05 候选审计、1224 条天然参考清洗、CD-HIT 90% 去冗余、418 条代表序列 MSA、23 个统计保守位点、PF00741/HMMER 和 BLAST+ 评价，以及三种筛选策略、消融、鲁棒性和随机基线实验。

现有流程存在以下主要问题：

1. 原候选来自混合 Gvp 数据训练的模型，不是已确认的纯 GvpA 候选；
2. PF00741 是 Gas_vesicle 家族模型，不是 GvpA 专一模型，也可能覆盖 GvpJ；
3. 候选只检查了空序列、非法字符和重复 ID，缺少长度、截断和低复杂度等质量控制；
4. `domain_pass` 只被记录，没有作为进入主排名的硬门槛；
5. 新颖性和多样性在混合家族候选池中计算，会错误奖励异家族或异常离群序列；
6. 当前 BLAST 局部比对和“无命中即最大距离”的处理可能高估多样性；
7. 参考集主要依赖 FASTA 头信息，缺少 GvpA/GvpJ 竞争性核验和负对照。

## 3. 修改后的总体流程

```text
高可信 GvpA 训练数据
        ↓
按同源簇划分训练集、验证集和测试集
        ↓
训练 VAE 或 GAN，并保存模型与训练记录
        ↓
生成候选序列及逐序列生成元数据
        ↓
格式、长度、截断、复杂度、组成和重复质控
        ↓
PF00741 家族域检查 + GvpA/GvpJ/其他 Gvp 竞争性鉴定
        ↓
划分主分析池、歧义探索池和排除池
        ↓
仅在适用的同家族候选中计算四维指标
        ↓
执行域、家族和质量硬门槛
        ↓
加权、Pareto 和轮转筛选
        ↓
正负对照、鲁棒性、复现性和结果报告
```

## 4. 工作一：使用 VAE 或 GAN 重新生成候选序列

### 4.1 模型选择

至少实现一种生成模型：

- 首选基线：序列 VAE。VAE 训练通常比离散序列 GAN 稳定，能够保存潜变量，并方便进行采样和潜空间分析；
- 可选对照：序列 GAN。只有在离散 token 采样和模式坍塌检查方案明确时再作为扩展实验；
- 如果两种模型都实现，应使用相同训练集、数据划分和候选数量进行公平比较。

模型选择必须在配置和报告中明确。需要保存模型结构、词表顺序、特殊 token、随机种子、训练轮数、优化器、学习率和 checkpoint 哈希。

### 4.2 训练数据要求

- 训练数据只能使用经过核验的 GvpA 序列；
- GvpJ、GvpN、GvpC 和其他 Gvp 家族不能混入 GvpA 训练集；
- 先按序列相似性聚类，再按簇划分训练、验证和测试集，避免近重复序列跨集合泄漏；
- 保留原始来源、原始 ID、清洗原因、家族证据和序列 SHA-256；
- 训练前固定词表和 BOS、EOS、PAD、UNK 等特殊 token 的编号；
- 不得用最终测试集调参或筛选 checkpoint。

### 4.3 模型训练评价

VAE 至少记录：重构损失、KL 散度及其权重、验证集重构准确率、潜变量坍塌检查、生成长度和氨基酸组成分布。

GAN 至少记录：生成器和判别器损失、模式坍塌检查、不同随机种子的生成多样性、生成长度和氨基酸组成分布、训练稳定性和 checkpoint 选择依据。

### 4.4 候选生成与逐序列元数据

每条候选除 FASTA 序列外，还必须记录：

| 字段 | 含义 |
| --- | --- |
| `sequence_id` | 稳定且唯一的候选 ID |
| `generator_type` | VAE 或 GAN |
| `model_checkpoint` | 使用的 checkpoint |
| `checkpoint_sha256` | checkpoint 哈希 |
| `generation_seed` | 生成随机种子 |
| `sample_index` | 批次内序号 |
| `temperature` | 采样温度，如适用 |
| `top_k` / `top_p` | 采样参数，如适用 |
| `latent_id` | VAE 潜变量样本编号，如适用 |
| `raw_token_length` | 包含特殊 token 前的长度信息 |
| `sequence_length` | 解码后的氨基酸长度 |
| `terminated_by_eos` | 是否正常生成 EOS |
| `hit_generation_cap` | 是否达到最大生成长度 |
| `sequence_sha256` | 序列哈希 |

建议生成多于最终筛选需求数十倍的初始候选，例如最终需要 Top-20 时生成 500～2000 条，再经过固定规则筛选。具体数量写入配置，不在代码中硬编码。

### 4.5 验收标准

- 模型训练可由配置文件和固定随机种子复现；
- checkpoint、词表和数据划分完整保存；
- 候选 FASTA 与元数据 TSV 一一对应；
- 不存在空序列、非法 token 或重复 ID；
- 正常结束和达到长度上限的候选能够被区分；
- 报告中不把“模型生成”直接表述为“功能有效”。

## 5. 工作二：增加候选质量控制

### 5.1 必查项目

每条候选至少检查：

1. FASTA 格式和唯一 ID；
2. 是否为空序列；
3. 是否只包含标准 20 种氨基酸；
4. 是否与另一候选完全重复；
5. 是否与训练序列或天然参考完全相同；
6. 长度是否位于预先定义的 GvpA 合理范围；
7. 是否达到生成最大长度，存在截断风险；
8. 是否出现异常长的单一氨基酸重复；
9. 是否为低复杂度序列；
10. 氨基酸组成是否严重偏离高可信 GvpA 参考分布；
11. 是否存在异常长的疏水片段或额外跨膜区；
12. 是否含有与目标无关的明显结构域；
13. 是否存在多个重复域或异常域架构；
14. 是否能够被后续比对和评分工具正常处理。

### 5.2 输出字段

质量控制表至少包含：

```text
sequence_id
length
standard_aa_only
duplicate_candidate
exact_training_match
exact_reference_match
generation_cap_warning
low_complexity_warning
composition_outlier_warning
hydrophobic_segment_warning
unexpected_domain_warning
qc_pass
qc_reasons
```

警告项和硬失败项需要在配置中区分。例如，达到生成上限必须产生警告；非法字符、空序列和完全重复通常作为硬失败。

### 5.3 验收标准

- 所有候选都有完整 QC 记录；
- 每个被排除的候选都有明确原因；
- QC 不覆盖或修改原始生成 FASTA；
- 长度范围及其他阈值来自配置文件；
- 生成上限候选不能被静默当作完整蛋白。

## 6. 工作三：重新处理参考集及家族可信度

### 6.1 参考集分层

参考序列应划分为：

```text
high_confidence_gvpa
possible_gvpa
gvpj_negative_control
other_gvp_negative_control
excluded_or_unresolved
```

高可信 GvpA 参考不能只凭文件名或头信息确定。至少综合：

- 原始数据库注释；
- 蛋白名称和亚家族标签；
- 长度和完整性；
- PF00741 命中；
- 与已确认 GvpA、GvpJ 参考的竞争性相似度；
- 是否存在冲突注释或其他结构域。

### 6.2 Pfam 能否只保留 GvpA

当前 PF00741/Gas_vesicle 不能单独做到“只保留 GvpA”，因为该家族模型也可能覆盖 GvpJ。后续需要核查当前官方 Pfam/InterPro 是否存在可用于 GvpA 亚家族区分的独立模型，但在核验完成前不能假定存在专一 Pfam。

若没有可靠的 GvpA 专一 Pfam，采用组合方案：

1. PF00741 作为 Gas_vesicle 家族入口门槛；
2. 建立高可信 GvpA 与 GvpJ 标注参考库；
3. 分别构建或使用 GvpA、GvpJ 亚家族 profile；
4. 对候选进行竞争性 HMM/序列比对；
5. 比较第一家族与第二家族得分差值；
6. 差值不足的候选标记为 `gvpa_gvpj_ambiguous`，不能强行归为 GvpA。

### 6.3 防止数据泄漏

- 如果高可信参考同时用于生成模型训练，必须记录这种关系；
- 模型性能评估使用按同源簇隔离的测试集；
- 生成候选的新颖性可以相对于全部已知天然 GvpA 计算，但不能把该结果解释为独立测试集性能；
- 用于阈值校准、保守位点定义和模型评估的数据角色必须在清单中区分。

### 6.4 验收标准

- 每条参考都有来源、分类、证据和排除原因；
- GvpA 与 GvpJ 负对照明确保留；
- 高可信 GvpA 参考能够单独导出；
- 保守位点只由高可信 GvpA 参考定义；
- 报告明确说明 PF00741 是家族证据而非 GvpA 专一证明。

## 7. 工作四：建立可参与排名的候选池

### 7.1 家族分类输出

候选分类至少包括：

```text
supported_gvpa
gvpa_gvpj_ambiguous
other_gvp
unsupported
```

逐候选记录：

```text
sequence_id
pf00741_status
pf00741_score
pf00741_coverage
best_family
best_family_score
second_family
second_family_score
family_margin
family_status
classification_reason
```

### 7.2 候选池定义

建立三个互不混淆的集合：

- 主分析池：`qc_pass` 且 `family_status == supported_gvpa` 且通过域门槛；
- 歧义探索池：`qc_pass` 且 `family_status == gvpa_gvpj_ambiguous`；
- 排除池：其他家族、无证据或 QC 不通过的候选。

主报告的 Top-K 必须来自主分析池。歧义探索池可以单独报告，但不能与主名单混合。

如果主分析池不足 K 条，应输出实际数量并明确报告“合格候选不足”，不得从排除池自动补齐。

## 8. 工作五：修改四维评价

### 8.1 约束满足度

保留 PF00741/HMMER 连续分数，用于比较候选的家族域证据强弱：

```text
constraint_score = 参考经验百分位 × 模型覆盖因子
```

同时将以下条件作为进入主分析池的硬门槛：

```text
domain_score >= 冻结阈值
model_coverage >= 冻结阈值
family_status == supported_gvpa
qc_pass == true
```

连续约束分数不能用于抵消硬门槛失败。

### 8.2 保守性

- 重新使用 `high_confidence_gvpa` 参考建立 MSA；
- 保守位点只能由天然高可信 GvpA 定义；
- 保存每个位点的共识、频率、gap 比例和参考覆盖；
- 报告 `conservation_score` 与 `conservation_coverage`；
- 统计保守位点不得表述为已实验验证功能位点。

### 8.3 新颖性

新颖性只对主分析池和明确标注的歧义探索池分别计算。主分析池中：

```text
novelty_score = 1 - 与高可信天然 GvpA 的最大覆盖校正相似度
```

其他 Gvp 家族和无证据序列的 `novelty_score` 标记为不适用，不能因为“不像 GvpA”获得高分。

### 8.4 多样性

候选级独特性只在同一分析池内部计算：

```text
uniqueness_score = 与同池其他候选的平均距离
```

最终集合多样性也只计算同一池内所选候选的平均两两距离。主分析池、歧义池之间不得混算后用于同一个排名。

## 9. 工作六：改进相似度与距离计算

### 9.1 当前问题

当前方法使用 BLAST 最佳局部比对，并将没有命中的候选对近似为 identity=0、distance=1。这可能把低复杂度、异家族或无法可靠比对的序列当成“最大多样性”。

### 9.2 修改方案

采用两阶段方法：

1. 使用 BLASTP 或 DIAMOND 快速检索最近参考和候选邻居；
2. 对进入评分和排名的候选对进行全局或半全局比对复核；
3. 同时记录 identity、query coverage、target coverage 和 alignment length；
4. 设置最低可靠覆盖门槛；
5. 无可靠比对时标记为 `distance_unresolved`，不直接赋最大距离；
6. 检查多个 HSP，避免只取一个局部片段造成偏差；
7. 保存距离矩阵对应的候选 ID 顺序。

具体距离公式、缺失值规则和覆盖门槛必须冻结在配置中，并通过人工构造的小例子测试。

## 10. 工作七：重新设计筛选策略

### 10.1 硬门槛在前

筛选顺序必须是：

```text
QC → 家族鉴定 → 域门槛 → 四维评分 → 多目标排序
```

不能先对全部候选排序，再查看域通过率。

### 10.2 三种策略

在主分析池内继续保留：

- 等权加权：作为简单、可解释的基线；
- Pareto 排序：展示多个目标之间的取舍；
- 分维度轮转：保证不同维度的高分候选得到覆盖。

四个分数虽然都在 `[0,1]`，但分布和信息来源不同。需要补充百分位标准化或分布标准化对照，检查等权是否造成某些维度实际支配结果。

### 10.3 输出要求

每份 Top-K 名单必须同时携带：

- QC 状态；
- 家族状态；
- 域得分和覆盖度；
- 四个原始维度分数；
- 聚合分数或 Pareto 层级；
- 入选原因；
- 生成模型和批次信息；
- 所有警告字段。

## 11. 工作八：正负对照与重新测试

### 11.1 科学对照

至少加入：

- 已确认 GvpA 正对照；
- 已确认 GvpJ 近缘负对照；
- GvpN、GvpC 等其他 Gvp 负对照；
- 随机或打乱序列负对照；
- 天然序列完全重复对照；
- 部分截断和异常长度序列对照。

预期行为包括：

- GvpA 正对照应进入 GvpA 支持组；
- GvpJ 不应仅因 PF00741 命中就被判为 GvpA；
- 其他 Gvp 家族不能依靠高新颖性或高独特性进入主名单；
- 完全重复天然序列的新颖性应接近 0；
- 重复候选的独特性应降低；
- 截断或异常长度候选应产生明确警告或被排除。

### 11.2 自动化测试

新增测试至少覆盖：

1. VAE/GAN 生成元数据完整性；
2. 生成序列解码和 EOS 处理；
3. 长度、非法字符、重复和低复杂度 QC；
4. GvpA/GvpJ 竞争性分类；
5. Pfam 命中不等于 GvpA 的规则；
6. 硬门槛过滤；
7. 合格候选不足 Top-K；
8. 新颖性只对适用家族计算；
9. 多样性只在同类候选池中计算；
10. 无可靠比对时的距离处理；
11. 正负对照的预期排序；
12. 小型端到端流水线；
13. 配置缺失和非法阈值；
14. 固定随机种子的复现性；
15. 输出表、FASTA、距离矩阵和 ID 顺序一致性。

## 17. 最终验收标准

项目完成时应满足：

1. 生成模型的数据、代码、词表、checkpoint 和采样过程可追溯；
2. 每条生成序列都有完整生成元数据、QC、家族证据和评分；
3. PF00741 命中不再被直接解释为 GvpA 身份；
4. 非 GvpA 和无证据序列不会因高新颖性或高多样性进入主名单；
5. 主名单只从通过 QC、家族和域硬门槛的候选中产生；
6. 新颖性相对于高可信天然 GvpA 计算；
7. 多样性只在同一家族候选池内计算；
8. 无可靠比对不再自动等价于最大距离；
9. 正负对照表现符合预期；
10. 合格候选不足时能够如实报告；
11. 关键实验可以复现，全部产物可通过 manifest 审计；
12. 报告始终区分“计算支持的候选”和“实验确认的功能蛋白”。
