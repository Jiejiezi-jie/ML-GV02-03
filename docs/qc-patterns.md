# C：序列模式告警与独立 QC 审计

本模块只补序列层面的可审计启发式告警，不依赖 VAE、家族分类或外部数据库。
**不等于跨膜预测、结构域鉴定、功能验证，也不意味着完整 QC 已完成。**

## 运行与兼容性

```bash
python experiments/run_quality_audit.py --config configs/gv02_03_pattern_qc.yaml --output-dir results/my_qc_audit
```

输出目录必须不存在或为空。命令仅运行 QC，无需 HMMER、BLAST、MAFFT；输出
`candidate_qc.tsv`、`eligible_candidates.fasta`、`summary.json` 和 `manifest.json`。
manifest 记录输入、配置、实现代码及输出 SHA-256。输入路径按仓库根目录解析；
也接受绝对路径。代码哈希针对实际运行文件字节，Windows 换行转换会改变代码哈希。

新配置也可供现有完整流水线使用；其 processed/result 目录与旧 QC 实验隔离。
本次仅验证 QC，不重新生成全套评分、图件和筛选名单。
原配置 `configs/gv02_03_qc.yaml` 及历史结果不变。

API 中三个检测的启用阈值默认 `None`，旧调用保持原行为；新配置显式启用。
新增检测只写警告，**不新增硬淘汰条件**。已有长度、低复杂度等硬门槛仍有效，
所以带告警的序列可能因其他原因被淘汰。

## 检测定义（暂定工程阈值，尚未用正式家族参考校准）

| 检测 | 新配置阈值 | 规则与边界 |
| --- | --- | --- |
| 连续疏水片段 | `hydrophobic_run_minimum: 18` | 仅由 `AVILMFWY` 组成的最大连续片段，长度 ≥ 18；任意其他残基打断片段 |
| 单残基连续重复 | `homopolymer_minimum: 6` | 相同残基最大连续段，长度 ≥ 6 |
| 短 motif 串联重复 | 最短总长 12、至少 3 拷贝、motif 长 2–6 | 完全一致且相邻的重复；只保留不可再约简的 motif，避免把单残基重复重复报告 |

这些值是透明、可调整的开发起点，不是已验证的生物学异常阈值。
疏水检测不是滑窗平均疏水性方法，可能漏掉被少数其他残基打断的疏水区域，
不能据此排除跨膜区。串联重复不覆盖近似重复、远距离重复或重复结构域。

串联重复在相同周期的连续区间只报最左相位及完整拷贝，末尾不足一份的残基不计入；
例如 `ACACACACA` 报 `AC × 4`，位置 1–8。不同周期的独立命中可以重叠。
阈值包含边界；启用阈值必须为正整数，拷贝数和最大 motif 长至少 2；拒绝布尔值。

## 字段约定

- `qc_pass`：仍仅取决于硬失败项。
- `qc_reasons`：为兼容旧消费者，继续包含硬失败项及告警，旧项顺序不变。
- `qc_warnings`：只包含告警，以分号分隔；不包含硬失败原因。
- `hydrophobic_*`、`homopolymer_*`、`tandem_repeat_*`：每组含
  `checked`、`warning` 和 JSON 编码的 `segments`。
- 坐标从 **1** 开始、两端均包含；JSON 包含 `start/end/length`，单残基重复另有
  `residue`，串联重复另有 `motif/copies`。
- 未启用、空序列或含非标准氨基酸时 `checked=false`，片段列表为空、告警为 false。
  **必须同时看 checked，不能把 false 告警解释为已检查并通过。**
- 旧 `low_complexity_warning` 字段名称虽含 warning，现有规则实际上将其作为硬失败；
  本次不改此规则，也不把该硬失败放进 `qc_warnings`。

## 本次开发验证

使用旧 T05 200 条混合候选，不代表已确认 GvpA 池。训练集对照为暂定 V2 split，
不代表旧 T05 模型的真实训练集；参考集也尚未完成正式家族校验。
结果见 `results/gv02_03_pattern_audit/`。未提供生成 metadata，因此本次不能验证 EOS。
200 条候选均完成三项模式检查：10 条有单残基重复告警，另外两项没有命中；
仍有 170 条通过、30 条被原有规则淘汰，逐条资格与旧 QC 结果一致。
原有组成偏离告警为 145 条。两次运行的四个输出文件 SHA-256 全部一致。
重复运行请使用新的输出目录；在相同输入路径、配置和运行环境中，四个输出应逐字节一致。
manifest 含绝对路径和环境版本，不承诺跨机器或跨操作系统逐字节相同。

后续仍需：正式参考阈值校准、跨膜/非目标及重复结构域分析、EOS 元数据检查，
以及按 A 的家族标签构建正式分析池。
